# JD Analyzer

채용 공고(JD) 본문을 입력받아 회사 조사(최근 이슈 / 사업 현황 / 인재상)를 자동화하고 Notion에 기록하는 스킬. 배경과 목적은 [`README.md`](./README.md) 참고.

## 트리거 조건

- 사용자가 JD 텍스트를 붙여넣으며 "분석해줘" 등으로 요청할 때
- 사용자가 JD 스크린샷(이미지)을 붙여넣으며 요청할 때

## 입력

- 기본: JD 본문 텍스트(Ctrl+A, Ctrl+C로 복사한 것을 붙여넣기).
- 대안: 본문이 이미지로 되어 있는 경우, 스크린샷 이미지에서 직접 내용을 읽어 동일 절차로 분석한다.
- 채용 사이트(잡코리아/사람인/링크드인 등) 링크만 주어진 경우: 로그인 장벽·페이지 구조 문제로 본문을 안정적으로 가져올 수 없으므로 링크를 열어 크롤링을 시도하지 않는다. 대신 사용자에게 본문 텍스트 또는 스크린샷을 요청한다.

## 처리 절차

1. **JD 파싱**
   - 공고 제목, 회사명(`company`), 포지션(`position`), JD 핵심 요약(`jd_summary`, 3~5문장: 역할·필요 역량·근무 조건 등)을 추출한다.
   - 회사명·포지션이 본문에서 명확히 특정되지 않으면 추측하지 말고 사용자에게 확인을 요청한다.

2. **웹 검색 (회사명 기준)**
   - `{company} 최근 뉴스`
   - `{company} 사업 현황`
   - `{company} 인재상 채용문화`
   - 각 결과에서 헤드라인/날짜/출처 URL을 함께 남긴다. 검색으로 확인되지 않는 항목은 "정보 없음"으로 명시한다 (추측 금지).

3. **결과 통합**
   - JD 파싱 결과 + 검색 결과를 아래 [Notion 저장 규칙](#notion-저장-규칙)의 속성/본문 구조에 맞춰 정리한다.

4. **Notion 저장**
   - Notion MCP가 연결되어 있는지 먼저 확인한다. 연결되어 있지 않으면 저장 단계를 생략하고, 정리된 내용을 화면에 출력한 뒤 Notion 연결이 필요하다고 안내한다.
   - "기업 공고 분석 도구" 페이지 하위의 "JD Analyzer" 데이터베이스에 **항상 새 페이지를 추가**한다. 동일 회사·포지션의 기존 페이지가 있어도 덮어쓰거나 갱신하지 않는다 — 분석할 때마다 새로 추가해 히스토리를 보존하는 것이 목적이다.

5. **결과 표시**
   - 저장 완료 여부와 함께 정리된 내용을 화면에 표시한다.

## Notion 저장 규칙

### 데이터베이스

"기업 공고 분석 도구" 페이지 하위의 "JD Analyzer" 데이터베이스 (기존에 생성되어 있음). 데이터베이스를 새로 만들지 않는다.

### 속성 (Property)

| 속성명 | 타입 | 채우는 규칙 |
|---|---|---|
| 이름 | Title | JD 본문의 공고 제목을 그대로 사용. 제목이 명확하지 않으면 "회사명 - 포지션" 형식으로 대체 |
| 회사명 | Text | JD에서 추출 |
| 포지션 | Text | JD에서 추출 |
| 채용 형태 | Select | 아래 "채용 형태 판단 규칙" 참고 |
| 지원 기간 | Date | 마감일이 명시된 경우만 채움 |
| 원본 링크 | URL | JD 원문 링크 (있는 경우) |
| 분석일시 | Date | 분석 실행 시점 (시스템 자동 기록) |

### 채용 형태 판단 규칙

- JD에 명확한 마감일이 있으면 → "지원 기간"에 채우고 "채용 형태"는 `마감일 지정`
- "상시채용"으로 명시된 경우 → "지원 기간"은 비워두고 "채용 형태"는 `상시채용`
- "조기마감 가능", "적합자 채용 시 마감" 등으로 명시된 경우 → "채용 형태"는 `채용시 마감` (마감일이 표기되어 있어도 확정 아님을 표시)
- 마감일 정보를 JD에서 찾을 수 없는 경우 → "채용 형태"는 `정보없음`

### 페이지 본문 (긴 서술형 내용)

표에는 넣지 않고 페이지 본문에 아래 구조로 작성한다:

```markdown
## JD 요약
(3~5문장)

## 최근 이슈
- (헤드라인) — (날짜) [출처](url)
- ...

## 사업 현황
(서술)

## 인재상
**핵심가치**: (키워드 나열)
**요구 스킬**: (키워드 나열)
**우대 성향**: (서술)
```

## 핵심 원칙 (Rules)

- **추측 금지**: 검색으로 확인되지 않는 정보는 임의로 채우지 않고 "정보 없음"으로 표기한다.
- **출처 기록**: 모든 검색 기반 정보(특히 최근 이슈)는 출처 URL을 함께 기록한다.
- **본문 우선**: 채용 사이트 링크 크롤링을 시도하지 않는다 — 본문 텍스트/스크린샷 입력만 신뢰한다.
- **중복 처리**: 동일 회사·포지션이어도 분석할 때마다 새 페이지로 추가한다 (덮어쓰지 않음, 히스토리 보존 목적).
- **개인 용도**: 로컬 Claude Code 환경에서의 개인 사용을 전제로 한다.
